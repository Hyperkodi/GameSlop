# Infra notes: score bridge, anti-cheat, Solana P2E (verified 2026-08-25)

## 1. How real portals expose score/medal APIs to embedded HTML5 games
- **Poki** (sdk.poki.com/html5): script from Poki CDN; API = init, gameLoadingFinished, gameplayStart/Stop, commercialBreak, rewardedBreak, login, getUser, **getToken() -> JWT**, shareableURL. **No leaderboard/score API at all.** Poki keeps scores out of the SDK; games run in an iframe and the SDK bridges to the host via postMessage internally (closed source).
- **CrazyGames SDK v3** (docs.crazygames.com/sdk/html5): script tag `sdk.crazygames.com/crazygames-sdk-v3.js`; modules ad / game / user / banner / data. **No leaderboard API**; `user.getUserToken()` returns a CrazyGames-signed JWT that your server verifies with their public key - the pattern to copy for "who is this player". Third-party wrappers: defold/extension-crazygames (15 stars, MIT), Pelican-Party/adlad-plugin-crazygames.
- **GameDistribution** (github.com/GameDistribution/GD-HTML5, 34 stars, MIT, pushed 2026-06): the only major portal SDK fully open-source; ads + lifecycle only, but its source shows a production iframe<->host postMessage bridge.
- **Yandex Games** (yandex.com/dev/games/doc/en/sdk/sdk-leaderboard): real leaderboard API - `ysdk.leaderboards.setScore(name, score)`, getPlayerEntry, getEntries; auth required; rate limits setScore 1/s, reads 20-60 per 5 min; **no anti-cheat, score is whatever the client sends**. Open wrappers: BasilYes/godot-yandex-games-sdk (124 stars), indiesoftby/defold-yagames (75), forcepusher Unity pkg (71), maxmonax/yagames-phaser-template (8).
- **Newgrounds.io** (github.com/PsychoGoldfishNG/NewgroundsIO-JS, MIT, 2025-09): ScoreBoard.postScore + Medal.unlock are "secure" components encrypted with the app's encryption key (AES-128/RC4) plus a session id. The key ships in the client, so this is tamper-resistance, not security; medals get farmed regularly.
- **itch.io**: no score/leaderboard API for HTML5 embeds (only butler upload tooling); devs use Newgrounds.io/GameJolt/own backend.
- **Cross-portal abstraction layers** worth mirroring: playgama/bridge (47 stars, LGPL-3.0, pushed 2026-08; leaderboards+auth+ads over Playgama/GD/CrazyGames), Pelican-Party/adlad (11 stars, MIT, plugin-per-portal), DarlesGames/darles-html5-multiplatform-template (MIT, 2026; adapters in js/platform/adapters/). MyArcadeScoreBridge (GPL-3.0, 2019) is the WordPress-arcade era `myarcade_submit_score(score)` one-liner - the API shape AddictingGames-style portals used.
- **Bridge recommendation**: ship a 2 KB `portal-sdk.js` the game loads (like Poki/CG do) that wraps `window.parent.postMessage({v:1,type:'score',sessionId,score,events}, PORTAL_ORIGIN)`; host validates `event.origin` and `event.source === iframe.contentWindow`. Generic libs if you want promises/handshake: inedu/frameTalk, microsoft/iframe-bridge, Penpal (Aaronius/penpal).

## 2. Anti-cheat realities for client-reported scores (tokens attract bots and console `submitScore(999999)`)
1. **Never trust the number.** Anything the browser sends can be forged from devtools; itch/Newgrounds/Yandex leaderboards are routinely polluted (itch.io post: https://itch.io/post/13110590). Treat client score as a *claim*.
2. **Signed, single-use play sessions**: server issues `sessionId` + HMAC'd nonce at game start (bound to user, game id, skin id, expiry); score submit must carry it; one submit per session, then it is dead. Blocks replay of a captured request.
3. **Server-side plausibility model per game**: max points-per-second, min elapsed time (server measured, not client), score monotonicity, score granularity (e.g. Snake score must be a multiple of the food value). Reject/flag outliers. GameDev.net thread on HTML5 cheating: https://gamedev.net/forums/topic/643789-how-to-prevent-cheating-in-html5-game/5073561/
4. **Deterministic replay verification** (the real fix for skill games): seed the RNG server-side, have the game stream/attach the input log, re-simulate headlessly to recompute the score (Phaser runs on Node via geckosio/phaser-on-nodejs, 110 stars; LittleJS/KAPLAY logic is plain JS). Polytrack / TETR.IO / Trackmania-style validation. Cost: only feasible for games you control the source of - which you do.
5. **Rate limiting + economics**: cap payouts per user/day and per game; make token award a function of *rank/percentile in a daily epoch* not raw score, so a cheat inflates only one slot; delay settlement by an epoch so flagged scores can be voided before tokens move.
6. **Identity friction**: wallet signature (SIWS) + Poki/CrazyGames-style JWT + device fingerprint + optional Turnstile/hCaptcha before reward claim; one wallet per account; small stake or gas cost to submit deters Sybil farms.
7. **Obfuscation is not security**: Newgrounds' client-side AES key, minified bundles, and integrity hashes only raise effort. Serve each game build with the session-bound nonce baked in so a saved cheat page cannot be reused.
8. **Anomaly review**: log all submits with input-log hash, IP/ASN, timing; auto-hold top-N of each epoch for replay verification before payout. Comprehensive risk list: https://genieee.com/top-security-risks-in-html5-multiplayer-games-and-how-to-fix-them/
9. Related research: "Detecting and preventing replay attacks" (patent overview) https://patents.justia.com/patent/20070256123 ; arXiv 2512.21377 on game anti-cheat https://arxiv.org/pdf/2512.21377

## 3. Solana play-to-earn / Web3 game SDKs (stars / license / last push / maintained?)
- **MagicBlock** (github.com/magicblock-labs) - the actively maintained Solana gaming org in 2025-26: Solana.Unity-SDK 197 stars MIT (2026-08-19); magicblock-engine-examples 54 MIT (2026-08-21; has spl-tokens, session-keys, rewards-delegated-vrf, gachapon, rock-paper-scissor); bolt 63 MIT (2026-05, on-chain ECS); session-keys 12 MIT (2026-05); ephemeral-rollups-sdk (2026-08-24); **SOAR** 39 MIT (Solana On-chain Achievements & Rankings: leaderboards + achievements + automatic reward distribution; last push 2024-04 - reference design, verify Anchor version). Docs: https://docs.magicblock.gg
- **Solana Foundation examples**: solana-developers/solana-game-examples 102 stars, MIT-in-README (2026-07-13): lumberjack, battle-coins (program mints SPL tokens to players), coin-flip (Switchboard VRF), seven-seas, idle-game, city-builder; solana-developers/solana-2048 (17 stars, 2024-05: on-chain high score with weekly resetting reward pool - the closest P2E precedent; uses Gum session tokens, "not audited"). Scaffold: `npx create-solana-game` (solana-developers/create-solana-game, 2025-05; solana-game-preset 20 stars 2025-03). Solana SDK list: https://solana.com/docs/clients/community/game-sdks
- **Honeycomb Protocol** (github.com/Honeycomb-Protocol): hosted Edge API + Unity SDK / hpl-starter-kit (6 stars, 2025-07); programs not public, low GitHub activity since mid-2025; popular in Superteam hackathons. Dependency risk.
- **Gum** (gumhq/gpl, GPL-3.0): shut down Sept 2023, all repos archived; session-keys taken over by MagicBlock (https://blockchain.news/news/solana-gum-protocol-shuts-down).
- **Phaser + Solana**: Bread-Heads-Studios/solana-phaser-template (6 stars, 2024-12, NO license file - pattern only, Phaser inside Next.js with TipLink wallet). Godot: Virus-Axel/godot-solana-sdk 78 stars MIT (2026-05). Cocos: mstevens843/cocos-solana-mwa-sdk (2026-05).
- **Open-source "earn tokens for playing" browser arcades on Solana**: nothing credible. Udukuzi/nova-glitch-arcade-v1.1 (0 stars, MIT, 7 games + Solana), sege2023/arcix, CyberpunksTeam/cyberpunks-2088-game (19 stars, no license) are hackathon-grade. solana-labs/break (336 stars, MIT, archived 2024) is a tx-speed demo, not P2E.
- **Practical P2E architecture**: keep gameplay off-chain; server validates score (section 2) then either (a) writes to a SOAR-style leaderboard PDA signed by your authority key and pays SPL tokens from a program vault per epoch (battle-coins pattern), or (b) simpler: off-chain ledger + periodic batched SPL transfers (Token-2022 or classic) via a hot wallet with per-epoch caps. Session keys (MagicBlock) remove wallet popups if you go on-chain per game.
