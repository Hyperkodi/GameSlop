Straight answers to the questions you asked

Archived: yes · Reusable: no

Are the addictinggames.com games available somewhere?

Flashpoint Archive holds 220,586 games and animations, including ~1,225 tagged from addictinggames.com and 15k+ from Newgrounds, all playable through Ruffle (in-browser via 9o3o). The ~413 GB "Ultimate" build is the private archive you want.

But Addicting Games is still owned by Enthusiast Gaming, most titles belong to third-party developers, and nothing is licensed for modification or commercial use. Archive it for reference; don't build the business on it. Details ↓

Yes — a lot

Is there a big pool of open-source games like these?

270 repos catalogued, 193 permissively licensed. The multi-game collections alone are the whole first catalog: LittleJSArcade (65 classic clones), channingbreeze/games (~98 Phaser mini-games), crisp-game-lib (110 micro-arcade games), GDevelop examples (288 projects), sausi-7/games (142 with a launcher), and ~500 MIT-licensed js13kGames entries.

Gaps with no licensed clone worth using: Galaga, Centipede, Bubble Trouble, Line Rider, Motherload, Learn to Fly, Helicopter, Fruit Ninja, Bloons TD. Those are clean-room builds on LittleJS or KAPLAY — each is a weekend of work.

Yes, if you pick for it

Can we re-brand them cheaply per sponsor?

Reskin cost is set by where the art lives. Filter the catalog to permissive + static + reskin ≥ 4 and you get games where the mascot is a PNG swap: KAPLAY's examples all share one "bean" sprite, LittleJS games use a single tiles.png, blockrain.js has a theme API, emoji-minesweeper takes an emoji array, GDevelop projects are pure JSON.

Standardize on one skin manifest and one sprite spec so a new sponsor is a folder of assets, not a ticket. Pipeline ↓

Yes, with real anti-cheat

Can we bolt play-to-earn on top?

Most picks already expose a score or game-over event you can postMessage out of the iframe. The problem isn't getting the score out — it's that anyone can send submitScore(999999) from devtools once tokens are on the line. Poki and CrazyGames solved this by never accepting scores from the client.

Plan: signed single-use sessions, per-game plausibility caps, deterministic replay for the top scores, and pay by daily-epoch rank, not raw score. On Solana, MagicBlock's engine examples and the Foundation's battle-coins / solana-2048 are the working precedents. Scores ↓ · Solana ↓

Don't use these

Which popular repos are traps?

High-star repos with no license file are all-rights-reserved: react-tetris (8.7k★), mk.js (1.5k★), meth-meth-method/super-mario, Flexbox Defense, ChineseDron/fruit-ninja, daleharvey/helicopter, kubowania/candy-crush, vue-wordle. Worth an email to the author, nothing more.

Non-commercial or trapped IP: VVVVVV, Glaiel's Flash sources, Kittens Game, PokeRogue, Cookie Clicker mirrors, Cut the Rope, Lemmings.ts. Mario clones ship Nintendo art — the code is fine (mariohtml5 is public domain) but every sprite must go, which you're doing anyway.

The original Flash library: where it is and what you can do with it

It is archived — almost all of it

  • Flashpoint Archive holds 220,586 games and animations (180k games) as of this week. Its database tags ~1,225 entries as sourced from addictinggames.com, 15.5k from Newgrounds, 7.9k Kongregate, 2.2k Armor Games, 759 Miniclip, 740 Coolmath. Two builds: Infinity (~14 GB launcher, downloads games on demand) and Ultimate (~413 GB, everything offline). Ultimate is the private archive you were asking about.
  • The games are not on GitHub — only the tooling is (FlashpointProject/launcher, MIT, 1,258★). The searchable DB is public: flashpoint-database.
  • Playable in a browser today: 9o3o (Dri0m/9o3o, 0BSD) is Flashpoint's experimental web front-end on top of Ruffle; Internet Archive has another 6,504 single-SWF games running in Ruffle.
  • Ruffle (18,452★, Apache-2.0/MIT) is the emulator everyone — Newgrounds, Kongregate, Armor Games, Addicting Games itself — uses. Self-host ruffle.js + wasm, call RufflePlayer.newest().createPlayer(), load the SWF. AS1/2 games ~99% work; AS3 ~90%.

But none of it is licensed for what you want to do

  • Addicting Games has been owned by Enthusiast Gaming since Sept 2021 (US$34.4M) and still is. After 2020 they hand-ported their top 10 (Helicopter, Impossible Quiz, Kitten Cannon, Tanks, Bloons…) to HTML5 and put ~30% of the catalog back via Ruffle. They released no source for anything.
  • Most AG titles were third-party submissions (SeeThru, Dan Fleming, Splapp-me-do, 2DPlay, IriySoft, Ninja Kiwi). Even EG cannot license them to you — it would be a per-developer deal.
  • Archives are preservation, not licenses. Hosting a Flashpoint SWF is tolerated; adding a sponsor's mascot and paying players for scores makes it a commercial derivative work — a DMCA and trademark magnet. Nitrome already had all their games pulled from Flashpoint.
  • Technically you could reskin a SWF without source using JPEXS FFDec (swap bitmaps, patch in an ExternalInterface.call("onScore")) and Ruffle would run it — but only do that for games you have written permission for.

The real open-source Flash-era games

  • Canabalt — Finji's official HaxeFlixel port canabalt-hf is MIT (code); art and music stay reserved, the name is a trademark. Ship it as "Mascot Run" with your assets.
  • Adam Saltsman's Flixel demos (Mode, EZPlatformer, FlxInvaders, FlxTeroids, Flappybalt) — all MIT, plus HaxeFlixel/flixel-demos which builds them to HTML5.
  • Originals born as HTML5: 2048 (MIT), Chrome's T-Rex runner (BSD), HexGL (MIT), Sandspiel (MIT), Nicky Case's games (CC0). Copyleft: Hextris, Candy Box 2, Onslaught Arena (GPL), A Dark Room (MPL).
  • Source-visible but not usable: VVVVVV (personal use only), Tyler Glaiel's entire Flash back-catalog (CC BY-NC-SA), Kittens Game, the Cookie Clicker / Universal Paperclips mirrors, Line Rider. Bloons, Impossible Quiz, Boxhead, QWOP, Motherload, Fancy Pants: fan clones only.

Practical path: archive Flashpoint Ultimate privately for reference and demand signals (which titles people still search for). Build the sponsor-branded, play-to-earn product on the permissive list below. Host Ruffle-emulated originals only where a developer has signed off.

Reskin pipeline: how to make branding a config change

Pick games by how their assets are organized

  • Reskin 5 — pure data. GDevelop examples (288 MIT projects, ~60 starting-* genre templates): every sprite, color and string is in the project JSON, swapped in a visual editor, exported to a static HTML5 folder. KAPLAY examples all use one swappable "bean" mascot sprite — literally the case you described. pixijs/open-games has an AssetPack pipeline with themed asset folders.
  • Reskin 4 — one spritesheet + palette. LittleJS games use a single tiles.png and synthesized ZzFX audio (no sound files to re-record). crisp-game-lib games draw from a tiny character-pattern array and a theme name.
  • Reskin ≤ 2 — hard-coded. Colors and shapes drawn inline in canvas code. Still doable, but every sponsor is a code change. Avoid for the pipeline; fine for one-offs.

Beware asset licenses that differ from code licenses. phaser3-examples code is MIT but its art is explicitly not licensed for commercial or ad-supported sites; canabalt-hf code is MIT, art is all-rights-reserved. Since you replace the art anyway, that is workable — just never ship the originals.

One skin manifest per sponsor

Standardize every game on the same shape so a new sponsor is a JSON file plus a folder of PNGs, not an engineering ticket:

{
  "sponsor": "rambo-kitten-crew",
  "token":   { "mint": "…", "symbol": "RKC", "pool": "…" },
  "name":    { "game": "Kitten Cannon Run", "player": "Rambo" },
  "palette": { "bg": "#1b1b1f", "primary": "#d7263d", "accent": "#f2b441" },
  "sprites": { "player": "rambo-idle.png", "player_run": "rambo-run.png",
               "enemy": "hairball.png", "pickup": "rkc-coin.png",
               "logo": "rkc-logo.svg" },
  "audio":   { "pickup": "meow.mp3" },
  "strings": { "title": "…", "game_over": "…", "cta": "Claim RKC" }
}
  • Wrap each adopted game in a thin loader that reads ?skin=rambo-kitten-crew, fetches the manifest, and injects it before the game's preload step (for engine games) or as CSS variables + image URL overrides (for DOM/canvas games).
  • Mascot art needs a fixed sprite spec per game archetype (idle / run / jump / hit at 64×64, 8 frames) so a sponsor's artist — or an image model — fills a template rather than redrawing per game.
  • Keep a THIRD_PARTY_NOTICES page listing every repo, license and author; for GPL titles link to your fork with the modified source. That is the whole compliance story for the permissive and GPL rows below.

Score bridge and anti-cheat

How the big portals do it

  • Poki and CrazyGames SDKs have no score API at all — they hand the game a signed JWT for identity and keep scores out of the client. That is the pattern to copy: your SDK gives the game a session token, never trusts a number back.
  • Yandex Games has a real leaderboards.setScore() — and no anti-cheat; it stores whatever the client sends.
  • Newgrounds.io encrypts postScore with a key that ships in the client. Obfuscation, not security; medals get farmed anyway.
  • Only GameDistribution's SDK is fully open source (MIT) — a production iframe↔host postMessage bridge to read. Cross-portal adapters worth mirroring: playgama/bridge (LGPL), Pelican-Party/adlad (MIT).
  • Your bridge: a ~2 KB gameslop-sdk.js every game loads, wrapping parent.postMessage({v:1, type:"score", sessionId, score, inputs}, ORIGIN). Host validates event.origin and event.source === iframe.contentWindow.

Tokens attract submitScore(999999) — plan for it

  1. Treat the client score as a claim. Anything in the browser is forgeable from devtools.
  2. Signed single-use sessions. Server issues a nonce bound to user + game + skin + expiry at game start; one submit per session, then it's dead.
  3. Per-game plausibility model. Max points per server-measured second, minimum elapsed time, score granularity (Snake score must be a multiple of the food value).
  4. Deterministic replay is the real fix. Seed the RNG server-side, have the game attach its input log, re-simulate headlessly to recompute the score. Feasible only because you own the source — LittleJS, KAPLAY, crisp-game-lib logic is plain JS; Phaser runs on Node via phaser-on-nodejs. Favor games with a small deterministic core: 2048, T-Rex runner, Hextris, Flappy, Snake, Breakout.
  5. Pay on rank, not raw score. Token rewards as a function of percentile in a daily epoch, settled one epoch late so flagged scores are voided before tokens move. Cap per user, per game, per day.
  6. Identity friction before payout. Wallet signature (SIWS) + device fingerprint + Turnstile; one wallet per account; auto-hold the top N of each epoch for replay verification.

Solana play-to-earn building blocks

What's actually maintained in 2026

  • MagicBlock is the only Solana gaming org still shipping: magicblock-engine-examples (MIT, pushed this month — SPL-token rewards, session keys, VRF gachapon), session-keys (removes wallet pop-ups per game), bolt (on-chain ECS), and SOAR — Solana On-chain Achievements & Rankings: leaderboards + achievements + automatic reward distribution. SOAR's last push was 2024, so treat it as a reference design and check the Anchor version.
  • solana-developers/solana-game-examples (MIT): battle-coins is a program that mints SPL tokens to players; solana-2048 keeps an on-chain high score with a weekly-resetting reward pool — the closest existing precedent to your model (unaudited). Scaffold: npx create-solana-game.
  • Honeycomb Protocol is a hosted API with little public code since mid-2025 — dependency risk. Gum shut down in 2023. No credible open-source Solana P2E arcade exists; the Phaser+Solana templates on GitHub are hackathon-grade and mostly unlicensed.

Recommended architecture

  • Keep gameplay off-chain. The server validates the score (previous section), then either (a) writes to a SOAR-style leaderboard PDA signed by your authority key and pays SPL tokens from a program vault per epoch — the battle-coins pattern — or (b) simpler to start: an off-chain ledger with batched SPL transfers per epoch from a hot wallet with hard caps.
  • One sponsor = one skin config + one token mint + one reward pool. Sponsor deposits supply into the pool; the epoch settlement drains it by rank.
  • Play-to-earn with real tokens also drags in sweepstakes/gambling rules per jurisdiction and app-store/ad-network policies. Scope that separately before launch.
