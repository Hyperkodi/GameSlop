# Aegis UI polish

Presentation-only pass for `preview.html?release=candidate-v4`.

## Changes

- Final-cascade stylesheet preserves existing Armara hourglass, environments, and unit art.
- Consistent warm surfaces, gold headings, cyan selections, red primary actions, readable control type, and visible focus.
- Refined title, campaign chapters, loadout, briefing, settings, result screens, battle HUD, and tower store.
- Balanced Divine Protocol rows, explicit Locked labels, and equipped card states.
- Bordered battlefield sized to the available viewport. Tactical authoring grid stays hidden.
- Phone store keeps the tower name and Build action below its sticky header. Descriptions use 13.92 px text rather than the earlier tiny card copy.
- Corrected the road texture's inner image offset; pattern placement remains world-anchored.
- Repaired the title screen's missing accessible heading target.

## Verification

- Bare `node --test` in both the working Aegis folder and an isolated copy of the staged tree: 953 passed, zero failures in each.
- All six legacy/shared-kit suites passed: 83 tests total.
- Browser journey uses actual navigation controls for title, campaign, training, settings, loadout, protocols, briefing, battle, and tower selection.
- Victory and defeat screenshots use explicit production-view fixtures. These are layout checks, not campaign-completion evidence, and do not grant progress.
- Viewports: 1920 x 1080, 1440 x 900, 1280 x 800, 768 x 1024, 390 x 844, 320 x 740, and 844 x 390 landscape.
- Checks cover horizontal overflow, minimum HTML control height, accessible heading targets, balanced protocol rows, hidden tactical grid, desktop/landscape battlefield fit, and store bounds/readability. Narrow portrait pages permit vertical scrolling.
- Keyboard focus, emulated forced colors, emulated Reduced Motion, and the in-game Reduced Motion/photosensitivity-safe toggles are exercised by the driver.
- Existing live tower-management driver passed on the working build: planning build, enemy movement, contextual pause, in-wave build and upgrade, animation-state sampling, cancelled sell, and confirmed exact refund.

Run the visual journey against a local server:

```powershell
node tools/cdp-shot.js "http://127.0.0.1:4173/games/aegis/preview.html?release=candidate-v4" 1440 900 "$env:TEMP/aegis-polish-final.png" --script tools/cdp-drivers/aegis-ui-polish.js --wait 100
```

Per-screen screenshots are written to the system temporary directory. The browser journey starts from a fresh profile and uses Mission 1 on Story with Assist for reproducible UI access.

## Scope

No simulation, balance, progression, graphics assets, or shared-kit files changed. Pre-existing local copy cleanups and tactical projection edits remain separate and unstaged. The scoped version is verified independently so the polish does not rely on those edits. This pass is local; no new public deployment is claimed.
